# Contributing

Contributions are welcome.

1. Fork the repository and create a focused branch.
2. Keep model-facing DSH tools unchanged; changes should stay behind official DSH Provider / extension seams.
3. Do not commit passwords, private keys, API keys, host-specific secrets, or local state files.
4. Run `npm run check` before opening a pull request.
5. Describe behavior changes and compatibility considerations in the pull request.

For security issues, follow [SECURITY.md](./SECURITY.md) instead of opening a public issue first.
